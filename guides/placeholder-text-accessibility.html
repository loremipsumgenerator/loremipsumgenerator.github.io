Placeholder Text and Accessibility

Dummy text can create real barriers. Learn how placeholder text affects screen readers, low-vision users and testing.

The screen reader problem

Screen readers read whatever text is on the page, including lorem ipsum. A blind user who opens a prototype filled with Latin hears meaningless words read aloud, which is confusing and wastes their time. Worse, if placeholder text reaches a live page, a screen reader user may think the site is broken or in a language they do not understand. Never use lorem ipsum in anything a screen reader user will encounter, including prototypes used for accessibility testing.

Placeholder attributes in forms

In HTML, the placeholder attribute shows grey hint text inside a form field, such as 'Enter your email'. This is not lorem ipsum, but it shares the same risks: the hint disappears when the user types, it is often too faint to read, and screen readers may not announce it reliably. Use a visible label for every field, and treat the placeholder as a short example, not as the instruction. Never put essential information only in a placeholder.

Contrast and readability of filler

Placeholder text in mockups is often shown in light grey, which can be hard to read for people with low vision. When you present a mockup, make sure the placeholder text has enough contrast to be read, or replace it with a note that says what the content will be. A mockup that only a sighted person with perfect vision can read is a poor tool for a team that includes people with different vision.

Testing with real users

User testing with placeholder text produces misleading results. Participants try to read the Latin, get confused, and their behaviour reflects the confusion rather than the design. For any test involving real users, replace the placeholder with realistic draft copy, even if it is rough. The test will measure the design, not the filler, and participants will give you useful feedback instead of asking why the site is in Latin.

An accessibility checklist for filler

Before any review or test, check three things: no placeholder text in anything a screen reader will read, no essential information hidden in a form placeholder, and no live page containing lorem ipsum. Add these checks to your launch and testing checklists alongside contrast and keyboard checks. Placeholder text is temporary by definition; accessibility problems caused by it are not.

Placeholder text and cognitive accessibility

Placeholder text can also affect people with cognitive disabilities, who may find unfamiliar Latin confusing or stressful. A page full of meaningless words is hard to navigate for anyone who relies on reading the content to understand where they are. For prototypes tested with people who have cognitive disabilities, use simple, realistic draft copy instead of Latin, and keep the language plain. Accessible design is not only about screen readers; it is about making content understandable for everyone.

Frequently asked questions

Can screen readers read lorem ipsum?

Yes, they read it aloud as words, which confuses users. Never put placeholder text in prototypes used for accessibility testing.

Is the HTML placeholder attribute accessible?

Not reliably. Always use a visible label for the field, and use the placeholder only for a short example.

Can I use lorem ipsum in user testing?

No. Replace it with realistic draft copy so participants react to your design, not to the filler.

Is lorem ipsum a cognitive accessibility issue?

It can be. Unfamiliar Latin confuses people who rely on reading content to navigate, so use simple draft copy in tests with real users.
